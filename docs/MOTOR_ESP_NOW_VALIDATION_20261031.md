# ESP32-C3 电机联动：软件验证记录

> 前序候选快照：以下 32,091 项测试及固件摘要对应本日较早的构建。电机联动代码在 CAN 自检期间继续更新，当前版本已包含 remote_ready/初始化失败降级等改动；本表不作为较新候选的最终验证记录，应以其最新构建清单重新核对。本次已完成的 slave1 CAN 硬件实测见 SLAVE1_CAN_TEST_20261031.md。

本轮用户要求先完成代码、稍后接线，因此新联动固件未烧录，真实电机联动尚未验证。此前已烧入屏幕的纯灯板程序不包含本次电机接收端，后续接线时仍需更新屏幕、C3 和独立电机 F1。

## 主机测试

- `tools/test-motor.py`：两分支各通过 32,091 项检查。真实控制、CAN、UART 回调/队列，旧速度目标回归，按键接管、心跳超时、错误/溢出/过期、控制周期异常取消旧转矩帧。
- `tools/test-motor-link.ps1`：11,573 项检查。显式协议、CRC/乱序/去重、STOP 屏蔽迟到 START、同模式手动重新开始、单向失败、各端重启、C 板确认与低压联动。
- `tools/test-motor-now.ps1`：1,228 项检查。无线外层长度/版本/CRC、重启绑定、旧接收端启动包丢弃、双向与单向断链、本地接管、恢复不自动启动；使用真实 F1 服务端、屏幕客户端和编解码器。
- `tools/test-motor-radio.ps1`：真实无线适配源码通过 23 + 16 项检查。灯板和电机端点共用一次初始化/回调，独立队列，指定目的 MAC，过期和溢出处理；主机 stub 不等于实际 RF 验证。
- 原协议/server/client 100,200 项断言，以及实际 energy_master、DBUS 解码、UART 分发测试通过；原 C 板业务与协议保持兼容。
- UI 70 张原生 240×320 画面和标签/字形边界通过；以 596b900 原源码及原字体渲染为参照，关闭电机显示时 35 张完全一致，开启时其余 35 张仅电机文字及启动就绪状态有变化。原有三个字号各 235 个字形的位图和度量全部相同。实体触摸命中未在本轮验证。

实际 ESP32-C3 只通过 USB 查询芯片身份，确认 COM45、ESP32-C3、4 MB、MAC `9C:96:D5:B1:65:EC`。没有向它写入本次接收端程序。F1 原速度参数文件 `motor_control.c` 未改。

2026-10-31 另行完成的 [slave1 板 CAN 自检](SLAVE1_CAN_TEST_20261031.md) 属于灯板 F1 的独立测试，不替代此处电机 F1 或三端联动验收。
